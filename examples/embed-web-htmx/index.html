Adaptive Cards × htmx

htmx drives the card-fetch lifecycle declaratively — every button below carries hx-get + hx-target attributes. The page intercepts htmx's htmx:beforeSwap event to replace the would-be HTML swap with a call to the WASM-backed Adaptive Cards renderer.

Net effect: htmx as the event + request engine, this repo's renderer as the content engine. Same posture most "X × htmx" integrations take when X is a client-side rendering library (charts, maps, code editors, etc.).

The htmx-side glue

<button hx-get="./cards/simple-text.json"
        hx-target="#ac-card-mount">simple-text</button>

<script type="module">
  import { loadAdaptiveCards } from "./ac-embed.js";
  const ac = await loadAdaptiveCards("./ac.wasm");
  document.body.addEventListener("htmx:beforeSwap", (evt) => {
    if (evt.detail.target.id !== "ac-card-mount") return;
    evt.detail.shouldSwap = false;           // cancel default HTML swap
    ac.render(
      evt.detail.serverResponse,
      document.getElementById("ac-card-mount")
    );
  });
</script>

Why intercept htmx:beforeSwap?

htmx's default behaviour is to splice the server's response into hx-target as raw HTML. Our card endpoints return JSON, not HTML — letting htmx splice the raw JSON text into the DOM would corrupt the page. By cancelling the default swap and routing the response into the renderer, we get all of htmx's nice declarative request/lifecycle goodies (hx-trigger, hx-indicator, hx-confirm, hx-on::after-request, etc.) without giving up the IR-walker contract.

What this proves

  • The ac-embed.js module is framework-agnostic: this page uses it from htmx-wired code paths, exactly as the React + vanilla example pages use it from their own frameworks. Same WASM module, same IR contract, same data-ac-node attributes, same ac-* classes.
  • The integration works for server-rendered hosts (Rails, Django, ASP.NET Core, FastAPI, etc.) — every htmx host fits this pattern. Your server returns the card JSON exactly as it would for any other JSON API; htmx + this glue handles the rest.
